# 论文查重程序设计说明

## 1. 目标与边界

程序接收三个命令行参数：原文文件、抄袭版文件和答案文件。程序读取前两个文件，计算重复率，并把结果写入第三个文件。答案文件只写一个保留两位小数的浮点数。

程序不联网，不扫描目录，不读取命令行参数以外的用户文件，不使用外部语料库，也不下载模型。

## 2. 总体流程

```text
命令行参数检查
      ↓
读取两个文本文件
      ↓
文本规范化
      ↓
jieba 分词并过滤无效 token
      ↓
统计两个文档的词频和文档频率
      ↓
构造两个 TF-IDF 稀疏向量
      ↓
计算余弦相似度
      ↓
格式化并写入答案文件
```

## 3. 算法设计

### 3.1 文本读取

优先按 UTF-8 读取。若输入是常见中文本地编码，读取层可以按明确的备用编码策略处理；所有读取都只针对命令行传入的输入路径。无法解码时抛出可识别的输入异常，而不是让程序产生半截结果。

### 3.2 文本预处理与分词

1. 统一换行和空白表示；
2. 使用 `jieba` 对文本进行分词；
3. 丢弃空白 token 和纯标点 token；
4. 保留中文词、英文词和数字词；
5. 不读取外部停用词表，保证运行时文件访问范围可控。

预处理规则集中在一个模块中，避免主程序和测试代码各自实现一套规则。

### 3.3 TF-IDF

将原文和抄袭版视为两个文档组成的小语料库。对每个词 `t`：

```text
tf(t, d)  = 词 t 在文档 d 中出现的次数 / 文档 d 的 token 总数
idf(t)    = log((N + 1) / (df(t) + 1)) + 1
weight(t) = tf(t, d) × idf(t)
```

其中 `N = 2`，`df(t)` 表示包含词 `t` 的文档数量。使用平滑后的 IDF，避免除零，并在代码中显式实现，不调用现成的 TF-IDF 向量化器。

向量使用字典保存非零项，减少不必要的内存占用。

### 3.4 余弦相似度

对两个稀疏向量 `A` 和 `B` 计算：

```text
similarity(A, B) = (A · B) / (|A| × |B|)
```

当任一向量为空或模长为零时，返回 `0.0`，防止异常退出。最终结果限制在 `[0.0, 1.0]` 范围内，只在输出阶段格式化为两位小数。

## 4. 模块接口规划

| 模块 | 主要职责 | 计划接口 |
|---|---|---|
| `file_io.py` | 读取输入、写入答案 | `read_text(path)`, `write_score(path, score)` |
| `text_processor.py` | 规范化和分词 | `tokenize(text)` |
| `tfidf.py` | 词频、文档频率和向量 | `build_tfidf_vectors(documents)` |
| `similarity.py` | 稀疏向量余弦计算 | `cosine_similarity(left, right)` |
| `errors.py` | 区分参数、读取、编码和输出错误 | 自定义异常类 |
| `main.py` | 参数检查和流程编排 | `main(argv=None)` |

## 5. 性能考虑

设两个文本的 token 总数为 `T`，不同 token 数为 `V`：

- 分词和计数预计为 `O(T)`；
- 建立稀疏向量预计为 `O(V)`；
- 余弦计算只遍历非零项；
- 不使用整篇文本的编辑距离，避免 `O(T²)` 的时间和内存开销。

首个可运行版本完成后，用 `cProfile` 检查分词、词频统计和向量构造的耗时，再决定是否优化。

## 6. 异常设计

需要覆盖以下场景：

- 命令行参数数量不正确；
- 输入文件不存在或无读取权限；
- 输入文本无法解码；
- 文本为空或清洗后没有有效 token；
- 输出文件无法创建或写入；
- 相似度计算出现零向量。

错误信息写到标准错误流，并以非零状态退出；成功运行时不输出调试信息。
